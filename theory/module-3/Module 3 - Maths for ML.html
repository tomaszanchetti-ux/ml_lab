Module 3 — Maths for ML

Revolut's topic 1 asks for "concepts like bias and variance". This module is the machinery every model shares, whatever its name: what a model is, how it learns (loss, gradient descent), why it fails (under- and overfitting — the bias–variance trade-off), how you keep it honest (validation, leakage), and how you measure it (the metrics). Module 4 then walks through the individual models — and each one will be "this machinery, with a different shape".

The one idea of this module

A model is judged on data it has never seen. Everything here — the split, the regularisation, the metrics — exists to answer one question honestly: how well will this work on tomorrow's customers?

Modules 1–2 gave you the pieces: a model's output is a conditional probability (M1); bias and variance are the two kinds of error (M2); a test set is a sample, so its metrics have confidence intervals (M2). This module assembles them.

C1What a model is

A model is a function with adjustable numbers inside: ŷ = f(x; w). You feed it features x (what you know about a case), it returns a prediction ŷ of the target y (what you want to know). The adjustable numbers w are the parameters (weights). Training = using past cases where y is known to find good values of w.

TermMeaningCredit-default example
Features (x)inputs known at decision timecredit limit, age, last 6 months of repayment status
Target / label (y)what you predictdefaulted next month: 1 / 0
Parameters (w)learned from datathe weight on "months late"
Hyperparameterschosen by you, before traininghow deep a tree may grow; the strength of regularisation
Training / inferencelearning w from history / applying the model to a new casefit on last year's loans / score today's applicant

The types of learning

  • Supervised — you have labels. Regression: the target is a number (LTV, amount, days to repay). Classification: the target is a category (fraud / not; default / not). Most business ML is supervised classification.
  • Unsupervised — no labels; find structure. Clustering (customer segments), dimensionality reduction, anomaly detection.
  • Self-supervised — the data labels itself: hide part of the input and predict it. That is how language models and PRAGMA are pre-trained (mask events in a customer's history, learn to reconstruct them).
  • Reinforcement learning — learn by acting and receiving rewards. One line is enough.
30 seconds — "what is supervised machine learning?""Learning a function from examples where the answer is known. I have historical cases with features — what I knew at the time — and a label — what happened. Training finds the parameters that make the model's predictions match the labels as closely as possible, and then I apply it to new cases where the label isn't known yet. If the label is a number it's regression; if it's a category, like default or no default, it's classification. Without labels it's unsupervised learning — clustering, for instance."

C2How a model learns: loss and gradient descent

The loss — one number that says how wrong the model is

LossFormulaUsed forCharacter
MSE — mean squared error(1/n) Σ (y − ŷ)²regressionpunishes big errors heavily (squared) → sensitive to outliers; predicts the mean
MAE — mean absolute error(1/n) Σ |y − ŷ|regressionevery euro of error counts the same → robust to outliers; predicts the median
Log loss (cross-entropy)−(1/n) Σ [ y log ŷ + (1 − y) log(1 − ŷ) ]classificationpunishes confident wrong answers enormously: saying 1 % when it happens costs log(0.01)

Log loss is the multiplication rule from Module 1 in disguise: the probability the model assigns to all the observed outcomes is a product; take the log and it becomes a sum; minimise the negative. That's maximum likelihood (Module 2).

Training = finding the weights that minimise the loss

Picture the loss as a landscape: every choice of weights is a location, the loss is the altitude. Training walks downhill.

repeat: w ← w − η · (slope of the loss at w) η = learning rate
  • The gradient is the slope: which direction makes the loss go up fastest. Step the other way.
  • The learning rate η is the step size. Too small: training crawls. Too large: it overshoots and bounces or diverges.
  • Stochastic gradient descent (SGD): compute the slope on a small random batch instead of all the data — noisier steps, but far cheaper; it's how neural networks train. Adam is SGD with an automatically adapted step size.
  • An epoch is one pass through the training data.
  • Linear regression has a closed-form solution (the "normal equation") — no iterations needed — but gradient descent scales better to huge data. Trees don't use gradient descent at all; they search for the best splits.
30 seconds — "what is gradient descent?""It's how most models are trained. I define a loss — a number measuring how wrong the predictions are — and I want the weights that minimise it. Gradient descent starts from some weights, computes the slope of the loss, and takes a small step downhill; then repeats. The step size is the learning rate: too small and it's slow, too large and it overshoots. Stochastic gradient descent does the same on small random batches of data, which is noisier but much cheaper, and it's what neural networks use."

C3Underfitting, overfitting, and the bias–variance trade-off

This is the concept they named. It is Module 2's dartboard, applied to models.

Underfitting — high biasOverfitting — high variance
What it ismodel too simple to capture the patternmodel so flexible it memorises the noise in the training data
Picturea straight line through a curvea wiggly line through every point
Train errorhighvery low
Test errorhigh (about the same as train)much higher than train — the gap is the symptom
If you retrain on new datayou get nearly the same (wrong) modelyou get a very different model each time
Fixmore complex model · better features · less regularisationmore data · simpler model · regularisation · fewer features · ensembling (bagging) · early stopping
expected test error = bias² + variance + irreducible noise
  • Bias: error from wrong assumptions — the model can't represent the truth. Variance: error from sensitivity to the particular training sample. Noise: randomness in the outcome itself that no model can remove (two identical customers, one defaults and one doesn't).
  • The trade-off: as you make a model more complex, bias falls and variance rises. Test error is U-shaped; the best model is at the bottom of the U, not at the lowest training error.
  • More data lowers variance (the flexible model has less room to chase noise) but does nothing for bias. Same statement as in Module 2.

How you diagnose it in practice

  • Train vs. validation error. Both high → underfitting. Train low, validation high → overfitting.
  • Learning curves (error vs. amount of training data). If the two curves have converged at a high error, more data won't help — you need a better model or features. If there's still a gap, more data will.
RevolutA fraud model shows AUC 0.99 on training data and 0.81 on last month's transactions. That gap is overfitting (or leakage — C5). A simpler model that scores 0.86 on both is the better model, even though its training number looks worse.
30 seconds — "explain the bias–variance trade-off""A model's error on new data has three parts: bias, variance and irreducible noise. Bias is error from the model being too simple — a straight line fitted to a curve; it underfits, and train and test errors are both high. Variance is error from the model being too flexible — it memorises noise in the training sample, so it does brilliantly on training data and much worse on new data; that gap is overfitting. Making a model more complex lowers bias and raises variance, so test error is U-shaped and I look for the bottom. To reduce variance: more data, regularisation, a simpler model or an ensemble. To reduce bias: a richer model or better features."

C4Regularisation — paying a little bias to buy a lot less variance

Regularisation adds a penalty for complexity to the loss, so the model prefers simple explanations unless the data insists:

loss = error on the training data + λ × (size of the weights)
L2 — RidgeL1 — Lasso
Penaltyλ Σ wᵢ²λ Σ |wᵢ|
Effect on weightsshrinks all of them towards zero, smoothly; none become exactly zeropushes some weights to exactly zero
Use it formany correlated features; general stabilityfeature selection — a sparse, interpretable model
Both togetherElastic net: λ₁ Σ|w| + λ₂ Σ w²
  • λ is a hyperparameter: 0 = no regularisation (may overfit); very large = all weights near zero (underfits). You choose it by validation (C5).
  • Scale the features first. The penalty treats all weights alike, so a feature measured in cents would be penalised differently from one in euros. Standardise (subtract mean, divide by σ) before regularised linear models. Trees don't need scaling.
  • Other forms of the same idea: limiting tree depth, early stopping (stop training when validation error starts rising), dropout in neural networks (randomly switch off units during training), more data, data augmentation.
  • In Module 2's words: regularisation deliberately introduces a small bias in exchange for a large reduction in variance. MSE = bias² + variance — the total can go down.
30 seconds — "what is regularisation, and L1 vs. L2?""Regularisation adds a penalty on the size of the weights to the loss, so the model only uses a feature if it really earns its place — it trades a little bias for a lot less variance and reduces overfitting. L2, or ridge, penalises squared weights: it shrinks them all smoothly and handles correlated features well. L1, or lasso, penalises absolute values: it drives some weights exactly to zero, so it does feature selection. The strength, lambda, is a hyperparameter I tune on validation data, and I standardise the features first so the penalty is fair."

  3. You increase λ from 0 to a huge value. Describe what happens to training error and to validation error along the way.
  4. Why standardise features before ridge or lasso, but not before a decision tree?

C5Validation — keeping yourself honest

Three sets, three jobs

SetUsed toTypical share
Trainingfit the parameters60–80 %
Validationchoose hyperparameters, compare models, pick the threshold10–20 %
Testestimate final performance — looked at once, at the end10–20 %

Why three and not two: every time you choose something because it did well on a set, you fit to that set a little. After fifty tuning decisions on the validation set, its score is optimistic. The test set has taken no part in any decision, so its number is honest. (It's the "multiple comparisons" problem of Module 2.)

Cross-validation

K-fold: split the training data into K parts (5 or 10). Train on K − 1, validate on the remaining one; rotate so each part is the validation set once; average the K scores. You use all the data for both training and validation and you get a sense of the score's variability. Costs K times the compute. Stratified K-fold keeps the class ratio the same in every fold — important for rare events.

Time matters

For anything that evolves — fraud, credit, customer behaviour — split by time: train on the past, validate on the more recent past, test on the most recent. A random split lets the model peek at the future and overstates performance.

Data leakage — the most common way to fool yourself

Leakage = information in the training features that would not be available at prediction time, or that comes from the target itself. The model looks superb offline and collapses in production.

KindExample
Target leakageA default model using "collections agency assigned" — that only happens after the default.
Time leakageRandom split on transactions: the model trains on Tuesday's fraud and "predicts" Monday's.
Group leakageThe same customer in both train and test: the model recognises the customer, not the pattern. Split by customer.
Preprocessing leakageComputing the mean for standardisation, or selecting features, on the full data before splitting.

Red flag: a result that's too good — AUC 0.99 on a hard problem — or one feature carrying almost all the importance. Assume leakage until proven otherwise.

After deployment: drift

The world changes: data drift (the inputs change — new customer mix, a new market), concept drift (the relationship changes — fraudsters adapt). A model's test score is a snapshot. Monitor inputs and outcomes in production; retrain on a schedule or when metrics degrade.

30 seconds — "how do you validate a model? why train / validation / test?""I hold data back. The training set fits the parameters; the validation set is for every choice I make — hyperparameters, features, the threshold; and the test set is touched once at the end for an honest estimate, because anything I tuned on is optimistically biased. With limited data I use k-fold cross-validation instead of a single validation split. For anything time-dependent, like fraud or credit, I split by time, not at random, and I keep each customer on one side only. And I'm suspicious of results that look too good — that's usually leakage: a feature that wouldn't exist at prediction time."

C6Measuring a regression model

MetricFormulaRead it as
MAEmean |y − ŷ|"on average we're off by €X". Same units as y. Robust to outliers.
MSEmean (y − ŷ)²squared units — hard to read; it's what most models optimise.
RMSE√MSEsame units as y; weights large errors more. RMSE ≥ MAE always; a big gap means a few large misses.
R²1 − SS_res / SS_totshare of the variance explained, vs. always predicting the mean. 1 = perfect, 0 = no better than the mean, negative = worse than the mean.
MAPEmean |y − ŷ| / |y|percentage error; breaks when y is near zero.

Squared vs. absolute error: if large misses are disproportionately costly (capacity planning, capital), use squared; if outliers are noise you don't want to chase (delays "up to 12 hours messing up the model"), use absolute, or cap / log-transform the target. Always compare against a baseline: predicting the mean or median for everyone.

C7Measuring a classifier

The confusion matrix — everything starts here

Actually positive (default)Actually negative
Predicted positiveTP — caughtFP — false alarm (Type I)
Predicted negativeFN — missed (Type II)TN — correctly left alone
MetricFormulaQuestion it answers
Accuracy(TP + TN) / allshare of all predictions that are right — misleading when classes are imbalanced
PrecisionTP / (TP + FP)of those I flagged, how many were real? — P(positive | flagged)
Recall (sensitivity, TPR)TP / (TP + FN)of the real ones, how many did I catch? — P(flagged | positive)
False-positive rateFP / (FP + TN)of the negatives, how many did I wrongly flag?
SpecificityTN / (TN + FP) = 1 − FPRof the negatives, how many did I correctly leave alone?
F12 · P · R / (P + R)harmonic mean of precision and recall — one number when you need both; low if either is low
Worked — the accuracy trap1,000 customers, 50 default (5 %). The model flags 100: 40 real defaulters and 60 false alarms. TP 40, FP 60, FN 10, TN 890.
Accuracy = 930 / 1,000 = 93 %. Precision = 40 / 100 = 40 %. Recall = 40 / 50 = 80 %. FPR = 60 / 950 = 6.3 %. F1 = 2·0.4·0.8 / 1.2 = 0.53.
The model "never flag anyone" has accuracy 95 % — higher — and catches nothing. With rare events, accuracy rewards doing nothing.

The threshold — one model, many operating points

A classifier outputs a score (a probability). You choose a threshold: flag everything above it. Lower the threshold → catch more (recall ↑) but with more false alarms (precision ↓). Raise it → the opposite. The threshold is a business decision: it depends on what a miss costs versus what a false alarm costs (the euro tables you built for ATO and delinquency). 0.5 is rarely the right one.

Threshold-free metrics: ROC and PR curves

  • ROC curve: plot recall (TPR) against false-positive rate for every threshold. AUC (area under it): 0.5 = random, 1.0 = perfect. Interpretation worth memorising: AUC is the probability that a randomly chosen positive gets a higher score than a randomly chosen negative. It measures ranking quality, independent of the threshold and of the class balance.
  • PR curve: plot precision against recall. Its baseline is the positive rate (a random model has precision = base rate). Use PR-AUC when positives are rare: ROC can look excellent (AUC 0.95) because the FPR's denominator is the huge negative class, while precision is still poor. PRAGMA's credit result is reported as PR-AUC for exactly this reason.
  • Calibration: are the probabilities honest? Among cases scored 20 %, do about 20 % happen? A model can rank perfectly and be badly calibrated. It matters whenever the probability is used as a number — expected loss, pricing.

Imbalanced classes — the standard toolkit

  • Right metrics: precision, recall, PR-AUC, cost-based — not accuracy.
  • Move the threshold rather than the data, first.
  • Class weights (make mistakes on the rare class cost more in the loss).
  • Resampling: undersample the majority or oversample the minority (SMOTE) — on the training set only, never on validation or test.
  • Stratified splits; more positive examples if you can get them.

More than two classes: a K×K confusion matrix; precision and recall per class, then averaged (macro = each class counts equally; weighted = by class size).

30 seconds — "how do you evaluate a classifier? is accuracy a good metric?""I start from the confusion matrix. Accuracy is fine when classes are balanced, but with a rare event it's misleading — if 1 % of transactions are fraud, predicting 'never fraud' is 99 % accurate. So I look at precision — of what I flagged, how much was real — and recall — of the real cases, how many I caught — and at the trade-off between them as I move the threshold, which I set from the business cost of a miss versus a false alarm. To compare models independent of threshold I use AUC — the probability a random positive outranks a random negative — and for rare positives the precision–recall curve, because ROC can look flattering there. If the probability itself is used, for pricing say, I also check calibration."

C8One-page cheat sheet

  • Modelŷ = f(x; w). Features in, prediction out; training finds w from labelled history. Hyperparameters are chosen, parameters are learned.
  • LossMSE (mean, outlier-sensitive) · MAE (median, robust) · log loss (classification; punishes confident mistakes).
  • Gradient descentStep downhill on the loss; learning rate = step size. SGD = on random mini-batches.
  • Underfit / overfitBoth errors high = high bias. Train low, test high = high variance. The gap is the symptom.
  • Bias–varianceerror = bias² + variance + noise. Complexity ↑ → bias ↓, variance ↑. Test error is U-shaped.
  • Fix variance / fix biasMore data, regularise, simplify, ensemble / richer model, better features.
  • L2 vs. L1Ridge shrinks all weights; lasso zeroes some (feature selection). Scale features first. λ by validation.
  • Train / val / testFit / choose / report once. K-fold when data is scarce. Split by time and by customer.
  • LeakageA feature not available at prediction time. "Too good" = suspect. Then drift after launch: monitor, retrain.
  • Confusion matrixPrecision = TP/(TP+FP). Recall = TP/(TP+FN). FPR = FP/(FP+TN). F1 = harmonic mean.
  • Accuracy trapWith a 1 % event, "always no" is 99 % accurate. Use precision / recall / PR-AUC.
  • Threshold · AUC · calibrationThreshold = business cost decision. AUC = P(positive outranks negative). Calibration = the probabilities mean what they say.
